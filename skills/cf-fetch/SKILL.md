# 取题（Fetch a problem）

## 两条通道

| 场景 | 做法 |
|---|---|
| 用户给了 CF 题号 / URL（`1800C`、`https://codeforces.com/contest/1800/problem/C`） | `cf_fetch { contestId, index }` |
| 用户直接粘贴了题面 | `cf_fetch { statement: "<粘贴的原文>" }`——走规范化通道，不需要网络 |
| 只有题号但 CF 抓取被反爬挡住 | `cf_fetch` 会自动查本地缓存；仍然失败时**请用户粘贴题面**（粘贴永远可行），不要反复重试 |

## CF 网页的抓取真相（不要在这上面浪费时间）

- `codeforces.com` 的**网页**在 Cloudflare 后面：桌面直连会拿到 `403 + cf-mitigated: challenge`。
- `codeforces.com/api/*` **不受影响**（元数据、rating、提交记录都从这里拿，稳定可用）。
- 应用内有一条"隐藏 Chromium + cf_clearance cookie"的抓取通道，成功过的题会**落盘缓存**（`data/cache/cf-problems/<题号>.json`）；已有缓存的题离线也能取。
- 所以：**先查缓存 → 再试网络 → 失败请用户粘贴**。永远不要因为抓不到就说"这题做不了"。

## 取到之后

1. **看完整性**：题面里有没有「输入格式 / 输出格式 / 数据范围」？样例抽到几组？
   缺少格式段或 0 组样例时，如实告诉用户，并说明后续会怎么兜底（用机械抽取 + 手算锚点）。
2. **抽契约**：`cf_contract`——把输入/输出/保证抽成结构化契约。它是后续所有步骤的唯一真相来源。
3. **落工作区**：题面与样例写入工作区（`cf_workspace`），这样：
   - 追问时题面**永远在上下文里**（这是历史上"题面截断"的根因，不要再犯）；
   - 同一道题第二次遇到可以直接复用已验证产物。

## 不标准题面的处理

粘贴的题面常常是自由文本（`输入描述:` 写在句子结尾、样例混在正文里）。流程：

```
机械识别（looksStandard）
  ↓ 不标准
题面整理 agent：重排成 标准结构（题意 / 输入格式 / 输出格式 / 数据范围与保证 / 样例）
  ↓
机械校验：样例必须能被真的解析出来；整合失败就用机械抽取 + 手算锚点兜底
```

整理出来的标准题面**必须落盘**（写进会话与工作区）——否则下一轮追问时这份题面就没了，模型只能看见用户那句提问（这正是旧版最严重的 bug）。
