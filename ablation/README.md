# 消融实验：cf-coach 到底比裸模型强在哪

这套脚本用来回答一个具体问题：**同一批题、同一个模型、同一份题面，加上 cf-coach 的 harness 之后，正确率提升多少、代价是多少 token。**

五档设计（这是当前实现的）：

| 档位 | 是什么 | 有没有工具 | 有没有 harness |
| --- | --- | --- | --- |
| **L0** | 裸模型：题面进去，回答出来 | 无 | 无 |
| **L0C** | L0 +「只输出一个代码块」这句格式硬要求（提示词纪律的最小干预） | 无 | 无 |
| **L0+** | L0 + **L2 题解 Agent 逐字相同的 system 与 user**（机械抽取的 I/O 契约 + 官方样例），一次调用、无工具 | 无 | 无 |
| **L1** | 裸 agent：同一个工具循环 + 通用工具（写文件/读文件/编译运行/对拍），提示词明确要求它自己对拍 | 有（4 个通用工具） | 无 |
| **L2** | cf-coach 本体：题面整理 → 正解/暴力/生成器三件套 → 对拍 → 证据门 → 图文讲解 | 有（cf_* 全套） | 有 |

> L1 故意复用 `lib/agentloop.js`（和 L2 同一个循环实现）与同一个 `data/config.json` 模型接口。
> **L0+ 故意复用 L2 的 `solutionSystem()` / `buildSolutionUser()`**（`lib/harness.js` 里同一份函数）。
> 这两条合起来，**`L2 − L0+` 才是"harness 的净贡献"**，`L0+ − L0` 是提示词纪律与输入整理的增量 ——
> 而不是"谁的循环写得好"或"谁的提示词更会哄模型"。

## 快速开始

```bash
# 0) 零 token 自测：本地假模型 + 自带示例题，验证整条管线（L0/L0C/L0+/L1/判分）
node ablation/selftest.js

# 1) 准备题目：复制清单，粘贴题面（题面不会进 git）
cp ablation/problems.example.json ablation/problems.json
mkdir -p ablation/statements ablation/oracle
#    statements/1800C.txt        ← 题面正文（从 cf-coach 会话里导出，或自己粘贴）
#    oracle/1800C.cpp            ← 外部 AC 提交（判分标尺，见下面「纪律」）
#    oracle/1800C.gen.cpp        ← 随机数据生成器

# 2) 先跑 5 题 pilot（强烈建议；管线的问题要在 5 题内暴露，别等 30 题）
node ablation/run.js --level L0,L0+,L1 --problems all --limit 5 --out ablation/out/pilot
#    档位：L0 裸模型 / L0C 裸模型+只输出代码块 / L0+ 裸模型+与 L2 同提示词 / L1 裸 agent / L2 cf-coach 本体
#    另有 --reps N（同题同档跑几遍）与 --call-timeout-min N（单次调用超时，默认 12）

# 3) L2 用 cf-coach 本体跑，然后把它的产物导进同一份记录
node ablation/import-l2.js --conv <会话id> --out ablation/out/pilot
#    或让消融自己跑 L2（推荐，记录更全）：
node ablation/run.js --level L2 --problems all --limit 5 --rich --depth L3 --out ablation/out/pilot
#    --depth L3 = 与产品默认一致（会多一次「讲解提纲」Agent）；--rich = 生成图文文档（判分不需要它）

# 4) 统一判分（三档同一套判据）
node ablation/judge.js --out ablation/out/pilot --iterations 200
```

想不花钱把 L0/L0+/L1 的管线再走一遍（不判分，只验证脚本）：

```bash
node ablation/mockllm.js --port 3999          # 另开一个终端
node ablation/run.js --base-url http://127.0.0.1:3999/v1 --api-key mock --model mock-gpt-4 --level L0,L0+,L1
```

## 人工测试台（UI）：一题一题地看 L0 vs L0+ vs L2

命令行适合批量跑；**人工看讲解质量**用测试台更快（加题 → 跑 → 左右对比 → 打分，全在一个页面里）：

```bash
npm run ablation:serve            # 默认 http://127.0.0.1:4311
# 只监听 127.0.0.1
# 模型与题面缓存都取自**应用真正在用的数据目录**：仓库 data/ 或打包产物 dist/<...>/data/，
# 哪个里有 providers 配置就用哪个（所以你跑打包版 exe 时不必再配一遍 key）；
# 想临时换模型：npm run ablation:serve -- --model deepseek-v4-pro（也支持 --base-url/--api-key）
```

启动时会打印用了哪个应用数据目录、哪个模型、缓存里已有哪些题；`/api/state` 的 `appDataDir`
也是同一个值（页面上「导应用缓存」那一行会显示）。如果两个目录都没有 providers，脚本会报错并列出
它找过哪些路径 —— 要么在应用里配一个服务商，要么用 `--base-url/--api-key/--model` 直接给。

页面上能做的事：

- **加题（题面和生成器都不用你手填）**：填题号（`1800C`）或题目链接 → 点「**从 CF 取题**」。
  它复用应用自己的取题通道（内嵌 Chromium 过 CF 反爬），题面、官方样例、标题、难度一次到手，
  **你只需要再贴一份自己的 AC 题解当 oracle**。贴完点「**自动写生成器**」：模型照题面 + oracle 写一个随机数据生成器，
  写完**当场跑代码体检**（能不能跑；不给任何命令行参数能不能跑 —— 判分就是这么调它的；数据会不会把 oracle 跑崩；
  是不是每次都产出同一组）。工具栏的「补生成器」一次把"有 oracle 但没生成器"的题全补齐。
  样例**留空就自动从题面解析**（`lib/statement.js`），也可以手工填 JSON 覆盖。题面/oracle/gen 都会落成文件（`runner` 只认文件）。
  取题失败多半是 CF 反爬偶发（实测同一轮里第一道过、第二道被 403 很常见），再点一次通常就过。
  > **贴 oracle 时的两个自动清洗**（都是"生成器一直体检不过"的真凶）：整块粘贴带进来的 ```` ``` ```` 围栏会被剥掉；
  > 语言下拉停在默认的 `python`、贴的却是 C++ 时，按代码内容自动纠正成 `cpp`（页面会提示改了哪一项）。
  > 老数据里已经带围栏/语言记错的 oracle，在启动时会**自动修好**（`lib/uistore.js` 的自愈，启动日志会打印）。
  > 体检报错也分清了责任：oracle 在**官方样例**上就跑不过时报 `oracle-broken` 并直接让你去查围栏/语言，
  > 不再一律说成"生成的数据把你的 oracle 跑崩了"。
- **取题被反爬拦死时的退路：导应用缓存**。应用自己抓成功过的题面会落盘成
  `data/cf-problems/<题号>.json`（`lib/cf.js` 的题面缓存，断网/被拦时应用自己也靠它）。对话框里的
  「**导应用缓存**」直接读这份文件 —— **纯本地读，不联网、不过反爬，秒回**；按钮旁边会列出缓存里已有的题号。
  只要你在应用里成功打开过一次这道题，就不必再跟 Cloudflare 纠缠。重新导入**不会覆盖你已经贴好的
  oracle / 生成器**（"先贴 oracle 再重新取题"是安全的）。两个渠道都不行时，把题面粘进输入框即可，其余功能照常。
  > 这轮顺带修掉了取题通道的两个真 bug —— 如果你之前"一直被拦"，大概率是这两个而不是账号问题：
  > ① `did-fail-load -3`（ERR_ABORTED）原先被当成**这一页加载失败**直接判死；其实它只是两段式的第二段
  > 把隐藏阶段还在飞的导航掐掉了（`cf-diag.log` 里"可见窗口刚起步 0.5 秒就报 -3"就是它）。现在 -3 与
  > 子框架失败都忽略。② 可见窗口的挑战等待预算原跟隐藏窗口共用 12 秒，人连"Verify you are human"
  > 都来不及点；现在可见窗口给 60 秒（隐藏阶段仍 12 秒）。
- **跑分**：勾选题目 → 跑选中题（或全部）。档位**多选**：`L0` 裸模型、`L0C` 裸模型+「只输出一个代码块」、
  `L0+` 裸模型+**与 L2 题解 Agent 逐字相同的 system/user**（契约 + 官方样例，无工具）、
  `L1` 裸 agent、`L2` cf-coach 本体。同机跑，进度走 SSE 实时刷新；
  L2 用 cf-coach 本体的整条链（三件套 → 对拍 → 图文讲解），产物（富文档、轨迹、交付代码）都能在页面里直接打开。
  > **`L0C` 是什么、为什么要它**：成本 A/B 里唯一有效的干预就是那句"只输出一个代码块"（0/2 → 2/2 交得出代码）。
  > 它和 `L0` 的 `system` 提示词**一字不差**，唯一差别是用户问法末尾追加一段格式硬要求 ——
  > 于是"不会做"和"没交出来"才是唯一变量，别的都没动。
  > **`L0+` 是什么、为什么要它**：判据是 `L2 > L0+`，因为只有 `L0+` 拿的是**同一套提示词与同一份输入**
  > （`lib/harness.js` 的 `solutionSystem()` / `buildSolutionUser()`，逐字复用）。它比 `L1` 更干净地隔离了
  > "提示词纪律 + 契约/样例投喂"的功劳：`L0+ − L0` 是提示词的增量，`L2 − L0+` 才是 harness 的净增量。
  > 它在记录里带 `systemFrom` / `userFrom` / `discipline` / `hasTools:false`，能自证用的是哪一套。
  > **重复次数（reps）**：同一个 (题 × 档) 跑几遍，用来区分"这次刚好蒙对"和"稳定会做"。
  > **重复方案（plan）**：`fill` = **补齐**（默认推荐）：同一个 (题 × 档) 已经有「重复次数」那么多条
  > **同模型同参数**的记录就跳过，只跑差额 —— 重复编号接着已有的往下排（已有 1 条、要 3 条，就补 `#2` `#3`）。
  > 没有要补的格子时它**直接不起跑**，日志写明"跳过了几格 / 本次补几条"。
  > 为什么要有它：跑过几轮之后，无脑重跑等于花钱重跑已经结算的格子（实测那台机器有一整轮两格就是在
  > 重跑上一轮的同一格）；而**判分是零成本的单独一步**，跟"要不要重跑"无关。
  > `full` = 每个格子都跑上面那个重复次数（原行为）；`sweep` = **全池先各跑 1 遍**
  > （先拿到一张全景图，再决定哪里值得补）；`ladder` = **只补阶梯缝**（已知最高 AC 与首次可信失败之间、
  > 含缝外紧邻一档的题跑 N 遍，其余各 1 遍）。30 题 × 4 档 × 3 遍按实测均值要 35 小时/台，
  > 而"哪一档的 rating 上限在哪"只需要缝附近的题有重复 —— 先 `sweep` 再 `ladder` 是默认打法。
  > ⚠️ `fill` 的判据指纹只有 `模型 | 服务商 | maxTokens`，**不含提示词版本**：改过提示词或改过判据口径
  > （例如 `7e70fa2` 的"题解只交代码"、`14e0b80` 的降级交付口径）之后要选 `full`，或者换一个新的
  > 数据目录 —— 否则新旧口径会混进同一张表，出的数没人认。
  > **并发（conc）**：默认 4，**不同题同时跑、同一道题的多档/多遍永远串行**（同题共享工作区，
  > 并行会互相清目录，数据会废得看不出来；锁是 `workspace.withKeyLock('abq:'+题号)`，只改调度、
  > 不改模型能看到的东西）。进度条显示的是"正在跑哪几道"，不是最后一条。
  > **判不了的题默认跳过**：题表里标了「判不了」（多解没 checker / 尺子贴错题）的题不会进队列，
  > 日志会写明跳过了哪几道；要跑就勾左上角「连判不了的题一起跑」。实测 2267B + 2268F 两道就烧掉
  > 91 分钟 / ¥10.6，且永远给不出可用结论 —— 那不是"少一个数据点"，是纯损失。
  > **单次超时（分钟）**：单个模型调用（不是整道题）的上限。撞上它会记成「中止」而不是「答错」——
  > 2267G 那次 12 分钟被掐断就属于这一类，嫌慢又不想丢数据就把超时调大（默认 12 分钟，最多 180）。
  > **传输层抖动会自动重试**（`lib/llm.js`，最多 3 次、退避 1.5s 起）：连接被掐、`fetch failed`、
  > `terminated` 这种"一个字都没收到"的失败，以前会被记成这一档"没做出来"（2268F 的 L0/L0C 就是这样，
  > 10 秒、0 token、0 成本却成了能力数据点）。现在这类只重试；**已经收到内容就不重试**（重试=重复计费），
  > 如实记成「中止」。
- **题解 Agent 与暴力 Agent 只交代码块**：问法从"先说算法与复杂度，再给一个完整代码块"
  一路收紧到 **"这一轮只输出一个代码块 —— 不写思路、不写算法、不写复杂度、不写前言后记"**
  （system 与每轮 user 里的格式段都这么写）。原因不是审美：
  输出长度上限是**硬上限**（服务商默认 65,536），推理型模型把预算烧在代码之前的思考上时，代码会被
  整段截掉 —— 实测 29 次题解调用里 **13 次两遍都没交出代码**（`sol-truncated-fallback-brute`），
  白跑 4,419s / 852k 输出 token（≈¥6.9，占 L2 阶段总时间的三分之一）。同一份提示词加一句
  "只输出一个代码块"的对照实验：0/2 → 2/2 交得出，token −18%、墙钟 −25%。
  代价是这两个 Agent 不再输出说明 —— 所以**算法描述与复杂度分析改由讲解提纲 Agent 负责**
  （它能看到已验证的题解代码、官方样例与验证报告，`outline.algorithm` / `outline.complexity`
  是它的必填字段，讲解正文再从提纲展开）。**这是模型可见的行为改变**，
  所以换问法前后的数据不要混在同一张表里。
- **"被截断"不许再靠抬上限来救**：原来 `lib/llm.js` 与 `server.js` 在"正文为空 + `finish_reason=length`"
  时会**去掉 `max_tokens` 原样重发**一次。这是最贵的一处浪费：去掉上限 = 把输出预算从 32,768 抬到服务商
  默认的 **65,536**，而病根是"问法太长、思考把预算吃光"，原样重发一个字都没改 —— 只是把同一笔钱再烧一遍。
  实测这一条重发在空转那 13 次上烧掉 **851,970 输出 token（≈¥6.9）**。现在这一层只把 `finish_reason`
  如实上报（`degraded: 'empty-truncated'`），真正的重试交给 `lib/harness.js`（换"先给结果 /
  【本次只要代码】"的极简问法、**并且带着同一个上限**重发）；e2e 里有硬断言：这一轮跑完，
  假模型那边"去掉 `max_tokens` 的请求数"不许增加。
- **rating 阶梯（这一档的 rating 上限在哪）**：页面下半部分按 rating 升序列出每道题 × 每档的格子。
  读法有纪律，别读歪：
  - `✓ AC` 只是**下界**（它证明"会做"，不证明"上限"）；上限只能由**可信失败**给出；
  - `中止/撞顶`（单次调用超时、撞长度上限）和 `不可判`（多解题、尺子坏了）**都不是答错**，绝不能被算成"不会做"；
  - 整道题只跑出中止/撞顶时，即使差分 WA 也不作数；同 rating 至少 3 题才谈得上"断崖"。
  规则只实现一次（`ablation/lib/ladder.js`，服务端算给界面渲染），诊断包里带的也是同一份。
- **左右对比**：左边 L0 的原始回答，右边 L2 的交付状态徽章 + 覆盖范围 + 图文文档 + 验证轨迹，
  下面是外部 oracle 给出的判分徽章（差分 AC/WA、样例 WA、**假自信**）与人工判定 `coach / tie / l0`。
- **判分 + 配对比较**：点一下就调 `ablation/judge.js` 的同一套判分，输出
  「不差于 L0 的比例 / 胜平负 / McNemar 精确 p / 每档 tokens 与花费 / 假自信率」，
  人工判定按题汇总进 `quality`（讲解质量轴）。
- **导出诊断包（发回日志）**：工具栏的「导出诊断包」把"这台机器上到底发生了什么"收成**一份纯文本**
  （环境 / **机器名** / 日志 / 题库与 oracle·生成器台账 / 每次跑的**逐步工具轨迹** / 判分与配对结果 /
  **rating 阶梯** / **本次的运行日志 `server.log`**），API key、cookie、邮箱、系统用户名都打码。
  下载完页面会回执"多大、多少行、含哪几段"；跑分结果不对时，把这份文件发出来就够了，不用截图。
  详见 [../docs/DIAGNOSTICS.md](../docs/DIAGNOSTICS.md)。
- **L1 的收尾兜底**：如果 L1 步数用尽时**既没落盘正解、正文里也没代码块**（2026-10-05 实测那次
  2268A 就是这样：20 步全花在辅助脚本上），它会**再追问一次「只要最终代码」**，把交付物救回来并
  单独留档（`codeSource: answer-final`，那次追问的 token 也计入 L1 成本）。这不是放水：
  交付物没有就是"这档没做出来"，跟"做出来了但代码错"是两种失败，别混。

### 在别人机器上跑出问题时：怎么把日志发回来

测试会在不同机器上跑，所以工作台**把终端输出同步落盘**到 `<--root 的数据目录>/server.log`
（启动日志里会直接印出这个路径，页面上「这台机器」那一行也有）。屏幕上滚过去的东西，事后还能查。

三件事：

1. **点「导出诊断包（发回日志）」**，把下载到的那个 `.txt` 发过来 —— 它已经把
   `server.log`（尾部 18 万字符）、rating 阶梯、逐条跑分明细（含 `rep=` / 撞长度上限 / 中止）都装进去了。
   文件名形如 `cfcoach-diag-20261012-093000-<机器名>.txt`，**多台机器同时测时分得清是谁发的**。
2. 不想开浏览器界面就直接拿文件：日志路径就是上面那个 `server.log`，**原样发来也行**（比诊断包短）。
3. 日志**写不进去时只降级**（只打屏幕、屏幕上会如实说一句），不会影响跑分 —— 但那种情况下就只能截图了。

> 诊断包刻意用**纯文本**而不是 zip：测试者要做的只是复制粘贴，不该被"先解压再找文件"卡住。


数据都落在 `--root`（默认 `ablation/out/ui`）：`problems.json`、`statements/`、`oracle/`、`gen/`、
`records.jsonl`、`verdicts.jsonl`、`compare.json`、`human.jsonl`、`answers/`、`docs/`。
**L2 有自己的隔离工作区**（`<root>/l2-data/workspace`，绝不碰你真实的 `data/`），
而且每跑一题前会先清掉这道题的工作区 —— 否则链会走"上次已验证"的缓存快路径，
测出来的就不是模型这次的表现了。

判分与配对比较的口径、"不差于 L0 才算没帮倒忙"这条合格线，见下面「判分口径（三关）」与「合格线」两节。

> 取题通道本身也有探针：`npm run probe:cf`（真机扒一道真题，验证"内嵌浏览器能不能过 CF 反爬"）。
> 它把第二道题算**软断言**：CF 反爬偶发（同一轮里第一道过、第二道被 403 很常见），那种失败只记 ⚠️，
> 不影响退出码 —— 探针红了才说明真的坏了。

## 产物长什么样

```
ablation/out/<时间戳>/
  records.jsonl       每次运行一行：题面 sha、模型、提示词、工具面、tokens、花费、耗时、最终代码
  answers/*.md        模型原始回答全文（人工复核、写论文附录都用它）
  transcript/*.jsonl  L1 的工具调用流水（时间、工具、参数、结果）——"它到底做了没做对拍"看这里
  sandbox/<name>/     L1 的工作目录（brute/gen/solution 都留着，可复现）
  summary.json        分档汇总：次数、成败、tokens、花费、总耗时
  verdicts.jsonl      判分结果（样例 + 差分），带反例输入
  compare.json        配对比较：不差于 L0 的比例、胜平负、McNemar p、每档成本、假自信率
  human.jsonl         人工判定（coach / tie / l0 / both-bad / both-good + 备注），测试台里点出来的
  server.log          工作台的终端输出（同步落盘、带时间戳；诊断包里会带它的尾部）

## 判分口径（三关）

**第 0 关（判分前必过）：尺子先验。** 差分对拍是拿 oracle 当标尺，所以判分器先拿**官方样例**跑一遍这把尺子：
跑不起来、或输出的答案跟官方样例对不上 → 这把尺子不可信（`oracle-broken`），这一题**不判候选**，
配对比较里也只写"判不了"，**不算进胜平负**。为什么必须这样：2268A 那份 oracle 只打印 `n,k` 的闭式、
完全不读数组，连自己的样例都过不了（期望 9/3/1/19，它给 10/3/7/8），而旧判分器照样拿它当标尺，
把 L0 与 L2 **两侧都做对了**的解答（用按题面独立写的暴力解验过 520 组）判成"差分 WA" —— 这就是
"错的尺子把正确解答判成错的"。多解题（题面写 `output any one of them` 之类）另有豁免：样例对不上不等于错
（`special-judge`），差分不一致也标 `diffUnreliable`，因为两边都可能是对的，没有 checker 时这一格**不可判**。

> **两个判据上的坑（2026-10-06，3500 分题 2268F 抓出来的）**：
> ① **"多解题"不只写在 `any` 里**。2268F 的题面只写了 "you do not need to minimize the number of
> operations"，于是被当成普通题做**逐字比对**，一条合法的构造答案（同样 k=3、只是操作顺序不同）被判
> "样例 WA"，整条链照着"样例没过"往下自纠错。现在 `lib/statement.js` 另有一条"不要求最优"的判据
> （`do not need to minimize` / `need not minimize` / `不需要最小化`…，旁边若有"字典序最小/唯一"仍按普通题判）。
> ② **尺子对了也可能漏标**：判分器原来只在"oracle 自己过不了样例"时才带 `special-judge` 标记，
> 于是"oracle 正常 + 题是多解题"这种最常见的组合反而按严格字面比对判（`ablation/judge.js` 已修）。
> 这道题的完整对账（四条记录逐条、三条硬证据、四个缺陷、要修的数据）见
> [../docs/counterexample-2268F-2026-10.md](../docs/counterexample-2268F-2026-10.md)。

1. **官方样例**：题目自带样例，跑过才算"至少对样例正确"。
2. **差分对拍**：用外部 AC 提交当标尺，配随机数据生成器，在小数据上跑几百组比对。
   这一关才是真判据 —— **样例是能骗过去的**（`selftest.js` 里就专门放了这样一份代码：
   样例全过、差分必被抓到，用来证明判据真的能判错）。
3. **人工抽检（可选）**：抽 5–10 题人工读代码，看是不是"真解"而不是"特判样例"。

同一题同一档**重跑**时，判分取的是"最新且真的产出了代码"的那条：这次失败（没给出代码块）的跑分
不会把更早的**成功**记录顶掉（否则配对表里会变成"这一档什么都没产出"）；被跳过的记录会在启动日志里列出账。
去重看的是**这条记录算不算"这一档给出的解"**，不只看"有没有代码"：链在题解 Agent 交不出代码时会
**降级交付自己生成的暴力解**（`delivered` 不是 `model-first`），它正确地慢，有代码、样例也可能 AC，
但它**不是这一档的解**。所以排序是「模型自己的解 > 有代码 > 降级交付的暴力解 > 没代码」——
否则一次"降级交付"就会把更早那条真解顶掉（2026-10-06 实测 2268C 07:15、2268E 08:20 的真解记录
就是这么丢的）。

**降级交付的暴力解不算"这一档解出来了"**（`ablation/judge.js` 的 `deliveredBrute` / `lib/compare.js`）：
它的样例与对拍结论只说明"这份暴力解是对的"，不说明这一档有能力。判分时它**不计 AC**、并在
"按档统计"与配对比较里单独列出（`⚠️降级交付暴力解 N`）——注意它**也不是"不可判"**：这是一个确凿的
"没交出来"。不这么做的时候，L2 会白捡两格 AC（实测 L2 2268C、2268D 就是这么被记成"做出来了"的）。

**这个口径必须落满三处，缺一处就会被误读**（2026-10-07 实测：只改配对比较时，用户看到"重判后结果
似乎没变化"）：

| 落点 | 表现 | 不落会怎样 |
| --- | --- | --- |
| 判分标题行（`ablation/judge.js` 的 `summarizeByLevel`） | `差分通过 6(75%)  严格 3(38%)（剔掉降级交付的暴力解）` | 那个 75% 会被当成能力证据引用出去 |
| rating 阶梯（`ablation/lib/ladder.js`） | 该格单列成 `⚠ 交的是暴力解`，**既不算 AC 也不算答错**，不进 `acMax` | "会做 ≤ r3500"这类结论会被一份暴力解撑起来 |
| 题卡徽章（`ablation/ui/index.html` 的 `verdictBadge(v, r)`） | `⚠ 交的是暴力解（不算 AC）` + 暗色附注原判词 | 题卡照样渲染成"差分 AC" |

阶梯的降级判据有**两路**：① 判分结果里的 `deliveredBrute`（`14e0b80` 起有）；② 判分还是旧口径时，
看这一格里**所有有代码的跑**是不是都降级交付（有一条真解就不算）。

判分结果里有一类容易被误读的徽章，这里说清楚：**`缺生成器`（`no-gen`，有 oracle 没生成器）与
`没有 oracle`（`no-oracle`）是分开的**。两者都跑不了差分对拍，所以都**只能算样例级证据**，
不能跟差分 AC 混在同一个比例里（配对比较里它们的 `strength` 都是 `samples`）。
判分按钮会分别提示缺什么、怎么补 —— 缺生成器点一下「补生成器」就能自动写。

### ⛔ 纪律：oracle 绝不能是 cf-coach 自己产出的

用 L2 自己写的暴力解/题解去评判 L2，等于自证，评审一眼就能否掉。
oracle 只能来自：

- Codeforces 上**真实 AC 的提交**（`lib/cfreview.js`/`cf_source` 已经能抓提交源码）；
- 题解博客里的代码（自己读一遍确认逻辑）；
- 你自己手写并单独验证过的实现。

`gen` 也一样：它决定"能考出什么错"，最好由你手写，而不是让 L2 生成。

## 合格线：**AC**（`L2 > L0+` 才算 harness 在解题上有价值）

产品口径先摆在这里：**除了 AC 之外，其它收益都记 0**。L2 没拿到 AC 而 L0 拿到了，就是净损失 ——
"L2 有降级解所以更好"这种说法不成立，因为让 L0 写降级解它一定写得出来。
所以主指标只有一个：**CF-AC**（尺子定义见「判分尺子：CF-AC」一节），
要看的比较是 **`L2 > L0+`** —— `L2 − L0+` 是 harness 的净贡献，`L0+ − L0` 隔离"提示词纪律 + 契约/样例投喂"。
下面几项是必须一起报的辅指标：

- **配对胜平负 + McNemar 精确检验（`p`）**：只有不一致的格子（`L0+` 错 `L2` 对 / `L0+` 对 `L2` 错）参与检验。
  不一致格子少于 6 时脚本会明确提示「p 没有判别力」——**别把"没发现差异"说成"证明相等"**。
- **假自信率**（`falseConfidence`）：链自己声称"已验证"、却被外部 oracle 判 WA 的比例。
  这是产品层面的失败（把错的盖章成对的），比"做不出来"严重得多，所以要单独报。
- **成本**（`byLevel` 的 tokens/花费，以及 **¥/AC**）：同一题 L2 比 L0+ 多花多少。
  2026-10 那次重判是 ¥1.81/AC vs L0 ¥0.37/AC（≈4.9×）而 AC 数没变 —— 这种结果必须原样写出来。
- **不差于 L0 的比例**（`notWorseRate`）：保留为"有没有帮倒忙"的粗指标，但它**不是合格线** ——
  "两边都没做出来"也算"不差于 L0"，拿它当验收线会把"一起失败"读成"没帮倒忙"。

## 让结论站得住的五件事

1. **配对（paired）**：同一批题跑齐三档，逐题比较，报告"哪几题从错到对"。
   每题的结局只有 对/错 两种 → 用**符号检验 / McNemar**，别只报一个总正确率。
2. **信息预算对齐**：三档拿到**同一份题面文本**（`statementSha` 记在记录里，能自证）、
   同一个模型、同一个服务商接口。注意一个已核实的事实：`lib/llm.js` 的请求体是
   `{model, stream, messages}` + 可选 `max_tokens`，**不发 temperature**，
   所以采样参数天然一致（记录里的 `requestFingerprint` 也说明了这点）。
   > ⚠️ **"每次调用的输出预算"也算信息预算的一部分，必须对齐。** 2026-10-07 踩过一次：
   > 单次调用臂（L0/L0C/L0+）**不传 `max_tokens`** → `lib/llm.js:159` 的请求体里根本没有这个字段
   > → 服务商默认 **65536**，而**思考与正文共用这一份预算**；L2 的题解 Agent 走的是
   > `lib/harness.js:980` 首轮 8192 + `:1060-1072` 撞顶抢救。结果：5 个格子**白卷**
   > （`finish_reason=length`、正文 0 字符），配对直接失真。
   > **现在三档统一走 `ablation/lib/levels.js` 的 `callWithBudget()`**（首轮 `ATTEMPT_MAX_TOKENS = 8192`；
   > 没有可交付代码块就抢救一次：`SALVAGE_MAX_TOKENS = 65536` + `reasoning_effort:'none'` +
   > 回灌上一轮思考尾 3000 字符），记录里用 `calls / salvaged / firstFinishReason / request.budget` 自证。
   > 只切这一个变量的对照实验在 `.probe/why-truncated.js`（同一套 system/user，跑 A/B/C/D 四种预算配置）。
3. **把 L1 的工具面写进文档**：L1 允许写文件/运行/对拍，不允许联网取题。
   工具面一变，L1 的含义就变了，结论也必须跟着重述。
4. **成本一起报**："正确率 +30 个百分点"必须配"多花多少 token/多少钱"。
   `summary.json` 里每档都有 tokens 与花费；只报正确率不报成本，等于只讲了一半。
5. **样本量与难度分层**：建议 24–30 题，分三档难度（800–1200 / 1300–1800 / 1900+），
   并混入"阴险题"（多解、精度、大 I/O、构造/交互类）。先 5 题 pilot，再放大。

  [`docs/cost-l2-salvage-2026-10.md`](../docs/cost-l2-salvage-2026-10.md)。

## 判分尺子：CF-AC（2026-10 修好 —— 在此之前所有"通过率"都要重看）

- 旧判分（`ablation/judge.js`）只有两关：官方样例 + 与外部 AC 提交在"生成器默认规模"上随机对拍。
  而 store 里的生成器**没有一个读 argv**（`runner.stressTest` 调生成器时不传参数），时限固定 5000ms ——
  于是**我们自己的降级暴力解也能被判 AC**（2268C 的 python 暴力解：样例过、对拍全一致，真实时限 2000ms 下跑不完）。
- 新尺子 `ablation/lib/ruler.js`，三条**同时**成立才算 CF-AC：
  ① 官方样例；② 与 oracle 在 `[30, 200, 2000]` 组随机数据上对拍；③ **题面最大规模 + 题目真实时限**
  （超时先用 20 秒宽松上限复跑，区分"刚超一点"与"差数量级"）。规模与时限来自题面解析
  （没有 `n` 只有测试组数 `t` 时用 t 的上界），可由 `<store>/limits.json` 覆盖；
  每个数字都带 `source`（override/cache/parsed/default），所以"这次判分是什么规模、什么时限"可以事后复核。
- **多解题判"不可判"**（`lib/statement.js` 的启发式 + `limits.json` 覆盖）：没有 checker 就没有资格说候选错。
- 重判工具：`node ablation/rejudge.js --store <目录>`（**串行**跑；别与压测/编译并发，否则 TLE 计时会被污染），
  配对表：`node .probe/cfac-pairs.js <store> L0,L0C,L0+,L1,L2 --agg best`（一格多条记录时必须显式选口径，
  `best` = 一格取第一次 CF-AC = pass@k；`first` = pass@1；`latest` = 最后一次）。
- 重判结果（93 条记录）：**预算对齐之后 L2 赢过同提示词的单次调用臂**
  —— 17 题配对（`L0+ vs L2`：双 AC 5 / 只有 L0+ 0 / 只有 L2 7 / 双失败 5，净 **+7**，McNemar 精确 **p = 0.016**）；
  L0 vs L2 = +5（p=0.125）；L0 vs L0+ = **−2**（p=0.625）；**六个降成本臂合计 0 AC**。
  成本 ¥/AC：L0 ¥0.21、L0C ¥0.26、L0+ ¥0.52、L1 ¥0.97、L2 ¥1.80（93 条实付 ¥49.825）。
  逐题矩阵与逐条论证见 `docs/cf-ac-ruler-2026-10.md` §3.6（§3.1–§3.4 是**预算没对齐**的旧纪律数字，已作废）。
- **重跑一个已经跑过的格（换纪律/换模型）不能直接 `--out` 指回原目录**：`openRun()` 是"新批次"语义
  （`records = []`），`run.js` 收尾会整体重写 `records.jsonl`，旧记录会被抹掉。
  先 `node .probe/budget-affected.js <store>` 列出受影响的记录，重跑进一个新目录，
  再用 `node .probe/store-merge.js <出目录> --base <旧 records.jsonl>[,…] --new <新批次目录>[,…]`
  按 (档位, 题目) **整格替换**合回去（同格多条记录会保留，供 pass@k 口径使用）。
- 尺子自身修了 5 处：值域 off-by-one（`<=` 被当成严格小于）、多解题被当错解、只有 t 的题规模取错、
  单次抽样太弱（改成最多重抽 4 次）、**本机栈 1–2MB vs CF 256MB** 让深递归正常解被误判 RE
  （`lib/runner.js` 加 `-Wl,--stack,268435456`，回归测试见 `scripts/test-runner.js`）。
- **已知局限**：最大规模只抽一份随机数据 → 失败标签会翻（AC/非 AC 这一列稳定）；下一步要抽 K 份、要求 all-pass。
- 全部数据与论证：[`docs/cf-ac-ruler-2026-10.md`](../docs/cf-ac-ruler-2026-10.md)。

## 这版**没有**做（别误读结论）

- **L1b（提示升级档）**：同样"被要求对拍"，但强调必须自己写暴力解与生成器并跑通 ——
  用来把"提示词的功劳"和"harness 的功劳"分开。**L0+ 已经承担了这件事的第一半**：
  它拿的就是 L2 题解 Agent 逐字相同的 system/user（机械抽取的 I/O 契约 + 官方样例），
  所以 `L0+ − L0` = 提示词纪律的增量，`L2 − L0+` = harness 的净增量。
- **自动抓题面/自动抓 AC 提交**：题面**已经能自动抓** —— 测试台里填题号点「从 CF 取题」，
  复用应用自己的取题通道（内嵌 Chromium 过 CF 反爬；命令行版见 `npm run probe:cf`）。
  oracle 仍然**必须人工准备**（外部 AC 提交），这是纪律不是懒：自产 oracle 等于自证。
  生成器不用手写 —— 测试台的「自动写生成器」让模型照题面 + oracle 写，写完当场跑代码体检。
- **自动统计检验**：已实现 —— `judge.js`（和测试台）会输出配对比较：CF-AC 逐格、配对胜平负、
  McNemar 精确检验 p（不一致格子 < 6 时提示没有判别力）、每档成本与 ¥/AC、假自信率。
- **非确定性抽样**：同一档同一题只跑一次。若要报方差，用 `--out` 分多个目录跑多次。

L0 ：对 a/n    平均 <p>k tokens   平均 <t>s   ¥<…>/AC
L0C：对 a'/n   …

      L2 vs L1（编排的增量）：…
