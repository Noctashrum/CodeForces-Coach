# CF Coach — 本地的 Codeforces 算法教练：先验证，再讲解

**[English](README.md) · [中文](README.zh-CN.md)**

CF Coach 是一个桌面应用（Electron + 零依赖 Node 服务），把一道 Codeforces 题目变成一堂**经过机器验证**的课。
它不直接让模型"讲讲这道题"，而是先写出题解、暴力解与数据生成器，**在本机让它们互相对拍**，通过之后才动笔讲解——
并且配上图解、可交互演示，以及一份如实说明"验证到什么程度"的报告。

所有内容（对话、代码、工作区、学员画像）都保存在本机 `data/` 目录；除了你自己配置的模型 API
（以及在取题时访问 Codeforces）之外，不向任何第三方发送任何数据。

```
抽契约 → 题解 ∥ 暴力解 ∥ 数据生成器（三个隔离 Agent，并发生成）
       → 官方样例校准 → 机械反作弊体检 → 规模阶梯随机对拍
       → 不一致时定位"谁错了"，只重写被判错的那一方，再重跑
       → 讲解：先立提纲，再输出图文文档（图解 + 交互演示），结构机械校验
```

---

## 与"让 AI 讲题"的区别

| 常见做法 | CF Coach |
| --- | --- |
| 模型说什么就信什么 | 题解必须在随机数据上与**独立写的暴力解**逐组一致 |
| 一个模型、一个上下文 | 四个隔离 Agent（题解 / 暴力 / 生成器 / 讲解），互相看不到对方的代码 |
| "样例过了"就算完 | 样例只用来校准标尺；正确性由对拍支撑，没跑到的部分如实标注 |
| 失败静默发生 | 每轮都给出结论：`ok` / `unverified` / `no-bruler` / `samples-failed` / `budget`，界面直接显示 |
| 聊天记录 | 结构化讲解 + 题目库 + 学员画像 + 每轮 token 与费用账目 |

## 功能一览

- **任意题目都能进来**：按题号 / 链接从 Codeforces 取题，或直接粘贴题面（粘贴题面会由专门的整理 Agent 归整，并做机械校验）。
- **真实的验证流水线**：本机编译运行（C++23 / Python 3 / Node）、样例校准、反打表扫描、行为体检、
  规模阶梯对拍（n = 8 / 20 / 50 / 200）、delta debugging 最小化反例。
- **富讲解**：自包含 HTML 文档渲染在沙箱 iframe 里——章节、SVG 图解、交互演示（序列点亮 / 柱状生长 /
  分步滑块 / 高亮漫游）、自测题、术语表。
- **学员画像**：宏观层面的优势 / 短板 / 讲解重点，且**只认你自己的行为证据**（你写的代码、你的提问、难度偏离），
  带 0 token 的证据闸门与幻觉守卫。
- **花费透明**：直接读服务商返回的 `usage`，按缓存命中价计费，消息上显示本轮总额、侧栏按 Agent 拆分，
  决策轨迹里每次调用都有角色、耗时、token 与模型名。
- **诚实降级是设计原则**：验证没收敛就说没收敛，并列出试过什么，而不是假装已验证。
- **本地优先**：便携文件夹、本地文件、无遥测、无账号，除模型 API 外零上传。

## 快速开始

```bash
npm install       # 首次安装 Electron（约 100MB，一次性）
npm run app       # 启动桌面应用
```

也可以直接用 `npm run pack` 产出的便携版：`dist/CFCoach-win32-x64/CFCoach.exe`，数据就在 exe 旁的 `data/`，
整个文件夹拷走即迁移。

**前置条件**：Node ≥ 18；想跑完整对拍还需要本机有 `g++`（C++23）与 `python3`——缺哪个应用会如实提示。

### 第一次使用

1. **设置 → 模型服务**：添加任意 OpenAI 兼容或 Anthropic 兼容服务（DeepSeek / Kimi / GLM / Qwen / OpenAI / Claude / 自建网关…）。
   可以给不同 Agent 角色分别指定模型（例如题解用强模型、生成器用便宜模型）。
2. **设置 → 通用**：填 Codeforces 用户名（决定讲解深浅与学员画像），选默认讲解语言。
3. 点 **「问一道题」**，输入题号（`1800C`）、粘贴链接，或直接粘贴题面。

## 一轮讲解是怎么跑的

| 步骤 | 做什么 | 谁来做 |
| --- | --- | --- |
| ① 抽契约 | 从题面机械抽取输入 / 输出 / 数据保证，作为全局唯一契约 | 编排器（0 token） |
| ② 三份产物 | 题解、暴力解、生成器**并行**生成，各自独立上下文 | 三个 Agent |
| ③ 样例校准 | 暴力解必须先过官方样例才允许当标尺；样例 ≤1 组时用**手算锚点**三方交叉验证 | 编排器 + 手算锚点 Agent |
| ④ 机械反作弊 | 硬编码扫描、退化输出检查、生成器体检、题解常量化检查 | 编排器（0 token） |
| ⑤ 规模阶梯对拍 | 逐档随机对拍；不一致时仲裁**谁错了**，只重写被判错的那一方 | 编排器 |
| ⑥ 最小化反例 | delta debugging 把反例缩到人能一眼看懂 | 编排器（0 token） |
| ⑦ 讲解 | 先立提纲，再写图文文档；结构与代码保真机械校验 | 讲解 Agent |

### Agent 之间的隔离

| 角色 | 看得到 | 看不到 |
| --- | --- | --- |
| **题解 Agent** | 题面 + I/O 契约 + 官方样例 | 暴力解、生成器、对拍结果 |
| **暴力 Agent** | 题面（**已移除样例段**）+ I/O 契约 | 官方样例答案、题解、生成器 |
| **生成器 Agent** | 只有契约里的**输入**部分 | 题意、输出格式、任何代码 |
| **讲解 Agent** | 题面 + 已验证题解 + 迭代轨迹 + 最小反例 + 你的画像 | 暴力解代码 |
| **提纲 Agent** | 题面 + 契约 + 样例 + 已验证题解 + 验证报告 | 暴力解代码 |
| **题面整理 Agent** | 你粘贴的原始文本 | 任何代码 |
| **手算锚点 Agent** | 题面 + I/O 契约 | 任何代码（独立推理） |
| **路由 / 做法评估 / 错因仲裁** | 只做判断，输出一行 JSON | — |

暴力解**拿不到任何官方样例**：能偷看答案的尺子就不再是尺子。它的校准在外部完成——编排器拿官方样例
比对它的**输出格式**，格式不符才把样例作为反馈给它。

### 让"尺子"保持可信的规则

- **只重写被判错的那一方**：对拍不一致时由仲裁判定是题解、标尺还是生成器的问题，只改那一方；
- **证据优先于意见**：编排器会机械检查**题解自己过不过官方样例**。若题解过了样例、而标尺未校准或在
  大数值上跑不动，则**不会**凭标尺的输出去改题解，而是如实以 `unverified` 收尾；
- **只是"慢"的标尺不算错**：暴力解在官方样例上纯 TLE（状态空间型暴力遇到 `10^9` 必然爆炸）时，
  它仍可用于小数值随机对拍，报告里如实写明这一分工；
- **绝不修改生成器的数据**：编排器把规模上限与数值上限作为 `argv[1]`/`argv[2]` 交给生成器，
  发现超限只**回报给生成器**，不会自己去改数据（二进制串、下标这类"数字串"会被改坏）；
- **尊重跨变量约束**：题面里出现和 / 积形式的约束（`a_i + a_j ≤ 10^9`、`Σn ≤ 2·10^5` …）时，
  任何"把数值压小"的建议会被自动放弃；
- **坏标尺量出的反例一律丢弃**，绝不写进讲解。

### 预算（单轮成本上限）

| 限制 | 数值 |
| --- | --- |
| 单轮模型调用 | 40 次 |
| 单轮墙钟 | 20 分钟 |
| 题解重写 | ≤ 3 次（与"换标尺"解耦） |
| 暴力解校准尝试 | ≤ 3 次 |
| 空回复 / 截断重试 | 每次调用 1 次、整轮 3 次 |
| 同一组反例重复出现 | 停止重写，如实降级 |

真实测得的量级（DeepSeek 系推理模型、约 2000 分题）：

| 情形 | 调用 | 输出 token | 墙钟 | 费用 |
| --- | --- | --- | --- | --- |
| 一次通过 | 7 次 | ≈11.5 万 | ≈6 分钟 | ≈ ¥0.9 |
| 标尺重写一次 | 9 次 | ≈32 万 | ≈7 分钟 | ≈ ¥2.4 |

## 讲解形式

**完整讲解 / 代码评估 → 图文文档（默认）**；**思路提示 / 题干解读 → 轻量文字**（这两类只给方向，文档范式用不上）。

- 文档是自包含的 HTML 片段，套上内置设计系统后渲染在 **沙箱 iframe** 里（允许脚本、无同源权限、CSP 禁止一切外部请求）；
- 校验是机械的：标签 / class 白名单、禁脚本与外部 URL、标签配对、图解数量（带合理 `viewBox` 的 `<svg>`）、
  SVG 文字越界。不通过先给一次定向修复，再**机械挽救**（净化 + 补齐闭合标签 + LaTeX 翻译），
  只有"确实一张图都没有"才回落成文字讲解；
- 消息正文只放一句引子；文档在生成过程中**实时写入 Agent 工作台**，看得见进度；
- 模型若写了 LaTeX（`$x$`、`\le`、`\lfloor`…），净化器会翻译成可读文本或设计系统的公式组件——
  因为图文文档里没有公式渲染器。

## 花费是怎么算的

每条消息下方显示 `💸 N 次调用 · ≈ ¥X`；侧栏给出本轮花费与**按 Agent 拆分**的明细，决策轨迹里每次调用都有耗时、token 与模型名。

- token 取自服务商的 `usage`；服务商不返回时按字符估算并明确标注；
- **缓存命中有单独计价**：DeepSeek 这类服务对命中的输入按折扣价计费，应用会读
  `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 分别计价；两者都没有时，估算会标注
  "**未含缓存折扣，实际通常更低**"；
- 单价：你在设置里填的 `providerId::model` 覆盖值优先，其次内置参考价；两者都没有就只报 token、
  显示"未配置单价"，不编数字；
- `max_tokens` 默认不指定（用服务商默认值）。推理型模型会把预算先花在思考上，上限设小了会出现"正文为空"，
  所以程序在检测到"被长度上限截断"时会自动换一种问法重试，并在必要时去掉上限。

## 隐私与本地数据

```
data/
├── config.json             # 设置：模型服务与密钥、CF 用户名、外观、单价
├── conversations/          # 每个会话一个 JSON
├── archive/                # 已归档会话
├── workspace/<键>/          # 验证工作区：sol / brute / gen / meta.json（轨迹、结论、最小反例）
│   └── cache/              # 同题已验证产物缓存（跨会话复用）
├── cf-problems/<题号>.json  # 抓成功过的题面 + 样例（之后断网也能用）
├── cf-fetch.log            # CF 抓取日志（哪一步成功、是否用了缓存）
├── profile-card.json       # 学员画像（宏观层面）
├── profile-log.jsonl       # 画像更新审计（应用了什么、拒收了什么、为什么）
└── window-state.json       # 桌面窗口位置
```

- 无遥测、无账号、无统计上报。唯一的对外请求是你配置的模型 API，以及取题时的 codeforces.com。
- Python / Node 生成的代码运行在受限沙箱里（独立临时目录、默认禁网）。
  **C++ 无法用这种方式限制**，只做超时与进程树清理——请只使用你信任的模型。
- 富文档运行在带 CSP 的沙箱 iframe 中，禁止一切外部请求。

### 从 Codeforces 取题

CF 挂在 Cloudflare 后面，普通 HTTP 请求可能吃 `403 + cf-mitigated: challenge`。应用按顺序尝试：
普通 HTTP（只请求桌面版，识别并拒绝移动版）→ 内嵌 Chromium 窗口（先隐藏窗口，再**可见但在屏幕外**的窗口，
因为 Cloudflare 的挑战常常会拒绝不可见窗口）→ 本地题面缓存 → 本会话缓存的官方样例 →
最后才提示你直接粘贴题面（这条路径永远可用、不依赖网络）。`data/cf-fetch.log` 会记录每一步的结果。

## 常见问题

- **取题被拦 / 403？** 会自动走内嵌浏览器通道，也可以配本地代理，或直接粘贴题面——粘贴走的是完全相同的流水线。
- **为什么回答里说"我没能验证通过"？** 验证是承诺而不是装饰：预算内没收敛就如实说，并列出试过什么。
- **为什么有时又慢又贵？** 推理型模型单次调用可能 5 分钟；预算把单轮限制在 40 次调用 / 20 分钟。
  最有效的省钱手段是给角色分别配模型（生成器用便宜的、题解用强的）。
- **什么都没生成出来？** 你会拿到一段机械摘要：卡在哪、已经跑了什么、可以怎么办，外加完整的决策轨迹——
  一轮讲解不会以空消息结束。
- **我的数据在哪？** 应用旁的 `data/` 目录；整个删掉即彻底重置。

## 已知边界

- 架构消除的是**实现缺陷的相关性**（暴力解写错、题解漏边界、溢出…），**消除不了题意误读的相关性**：
  几个 Agent 共享同一份题面与同一套先验，题面本身有歧义时会一致地犯同一个错。官方样例是模型之外唯一的锚点。
- 官方样例只能证明输出格式，不能证明正确性——所以它始终与机械检查和对拍叠加使用。
- **交互题不支持**（需要实时交互的题目无法用标准输入输出对拍）。
- **C++ 代码无法沙箱化**：生成的代码会在你的机器上真实运行。
- 长推理模型的输出截断仍是真实的失败模式：程序会用"只要代码"的问法与更大的输出上限重试，
  再失败就如实降级说明。
