# CF Coach — 本地的 Codeforces 算法教练：先验证，再讲解

**[English](README.md) · [中文](README.zh-CN.md)**

CF Coach 是一个桌面应用（Electron + 零依赖 Node 服务），把一道 Codeforces 题目变成一堂**经过机器验证**的课。
它不直接让模型"讲讲这道题"，而是先写出题解、暴力解与数据生成器，**在本机让它们互相对拍**，通过之后才动笔讲解——
并且配上图解、可交互演示，以及一份如实说明"验证到什么程度"的报告。

所有内容（对话、代码、工作区、学员画像）都保存在本机 `data/` 目录；除了你自己配置的模型 API
（以及在取题时访问 Codeforces）之外，不向任何第三方发送任何数据。

```
抽契约 → 题解 ∥ 暴力解 ∥ 数据生成器（三个隔离 Agent，并发生成）
       → 官方样例校准 → 机械反作弊体检 → 规模阶梯随机对拍
       → 不一致时定位"谁错了"，只重写被判错的那一方，再重跑
       → 讲解：先立提纲，再输出图文文档（图解 + 交互演示），结构机械校验
```

---

## 与"让 AI 讲题"的区别

| 常见做法 | CF Coach |
| --- | --- |
| 模型说什么就信什么 | 题解必须在随机数据上与**独立写的暴力解**逐组一致 |
| 一个模型、一个上下文 | 三个隔离 Agent（题解 / 暴力 / 生成器）互相看不到对方的代码；讲解 Agent 只依据**已验证过的产物**写文档 |
| "样例过了"就算完 | 样例只用来校准标尺；正确性由对拍支撑，没跑到的部分如实标注 |
| 失败静默发生 | 每轮都给出结论：`ok` / `unverified` / `no-bruler` / `samples-failed` / `budget`，界面直接显示 |
| 聊天记录 | 结构化讲解 + 题目库 + 学员画像 + 每轮 token 与费用账目 |

## 功能一览

- **任意题目都能进来**：按题号 / 链接从 Codeforces 取题，或直接粘贴题面（粘贴题面会由专门的整理 Agent 归整，并做机械校验）。
- **真实的验证流水线**：本机编译运行（C++23 / Python 3 / Node）、样例校准、反打表扫描、行为体检、
  规模阶梯对拍（n = 8 / 20 / 50 / 200）、delta debugging 最小化反例。
- **富讲解**：自包含 HTML 文档渲染在沙箱 iframe 里——章节、SVG 图解、交互演示（序列点亮 / 柱状生长 /
  分步滑块 / 高亮漫游）、自测题、术语表。
- **学员画像**：宏观层面的优势 / 短板 / 讲解重点，且**只认你自己的行为证据**（你写的代码、你的提问、难度偏离），
  带 0 token 的证据闸门与幻觉守卫。
- **花费透明**：直接读服务商返回的 `usage`，按缓存命中价计费，消息上显示本轮总额、侧栏按 Agent 拆分，
  决策轨迹里每次调用都有角色、耗时、token 与模型名。
- **诚实降级是设计原则**：验证没收敛就说没收敛，并列出试过什么，而不是假装已验证。
- **对话可以整理**：左侧支持**文件夹分类**（新建 / 重命名 / 删除，删文件夹不删对话）与
  **多选批量操作**（全选当前可见、批量归档、批量删除、批量移动到文件夹），几十条对话也不会乱。
- **本地优先**：便携文件夹、本地文件、无遥测、无账号，除模型 API 外零上传。

## 快速开始

```bash
npm install       # 首次安装 Electron（约 100MB，一次性）
npm run app       # 启动桌面应用
```

也可以直接用 `npm run pack` 产出的便携版：`dist/CFCoach-win32-x64/CFCoach.exe`，数据就在 exe 旁的 `data/`，
整个文件夹拷走即迁移。

**前置条件**：Node ≥ 18；想跑完整对拍还需要本机有 `g++`（C++23）与 `python3`——缺哪个应用会如实提示。

### 第一次使用

1. **设置 → 模型服务**：添加任意 OpenAI 兼容或 Anthropic 兼容服务（DeepSeek / Kimi / GLM / Qwen / OpenAI / Claude / 自建网关…）。
   可以给不同 Agent 角色分别指定模型（例如题解用强模型、生成器用便宜模型）。
2. **设置 → 通用**：填 Codeforces 用户名（决定讲解深浅与学员画像），选默认讲解语言。
3. 点 **「问一道题」**，输入题号（`1800C`）、粘贴链接，或直接粘贴题面。

## 一轮讲解是怎么跑的

| 步骤 | 做什么 | 谁来做 |
| --- | --- | --- |
| ① 抽契约 | 从题面机械抽取输入 / 输出 / 数据保证，作为全局唯一契约 | 编排器（0 token） |
| ② 三份产物 | 题解、暴力解、生成器**并行**生成，各自独立上下文 | 三个 Agent |
| ③ 样例校准 | 暴力解必须先过官方样例才允许当标尺；样例 ≤1 组时用**手算锚点**三方交叉验证 | 编排器 + 手算锚点 Agent |
| ④ 机械反作弊 | 硬编码扫描、退化输出检查、生成器体检、题解常量化检查 | 编排器（0 token） |
| ⑤ 规模阶梯对拍 | 逐档随机对拍；不一致时仲裁**谁错了**，只重写被判错的那一方 | 编排器 |
| ⑥ 最小化反例 | delta debugging 把反例缩到人能一眼看懂 | 编排器（0 token） |
| ⑦ 讲解 | 先立提纲，再写图文文档；结构与代码保真机械校验 | 讲解 Agent |

### Agent 之间的隔离

| 角色 | 看得到 | 看不到 |
| --- | --- | --- |
| **题解 Agent** | 题面 + I/O 契约 + 官方样例 | 暴力解、生成器、对拍结果 |
| **暴力 Agent** | 题面（**已移除样例段**）+ I/O 契约 | 官方样例答案、题解、生成器 |
| **生成器 Agent** | 只有契约里的**输入**部分 | 题意、输出格式、任何代码 |
| **讲解 Agent** | 题面 + 已验证题解 + 迭代轨迹 + 最小反例 + 你的画像 | 暴力解代码 |
| **提纲 Agent** | 题面 + 契约 + 样例 + 已验证题解 + 验证报告 | 暴力解代码 |
| **题面整理 Agent** | 你粘贴的原始文本 | 任何代码 |
| **手算锚点 Agent** | 题面 + I/O 契约 | 任何代码（独立推理） |
| **路由 / 做法评估 / 错因仲裁** | 只做判断，输出一行 JSON | — |

暴力解**拿不到任何官方样例**：能偷看答案的尺子就不再是尺子。它的校准在外部完成——编排器拿官方样例
比对它的**输出格式**，格式不符才把样例作为反馈给它。

### 让"尺子"保持可信的规则

- **判谁错之前先归一化**：两边输出先按 token 流比对（换行与空格只是版式，不是答案不同），字符串忽略大小写，
  数值按 `max(1e-6, |期望| × 1e-6)` 的容差比；剩下的差异会被分类（版式 / 大小写 / 精度 / 真差异）。
  行尾多一个空格永远不会被当成答案错误——"假失败"是这条流水线最大的噪声源；
- **标尺允许慢**：题解与生成器仍按 5 秒掐表，暴力解标尺给到 **20 秒**。状态空间型暴力按设计就是慢的，
  以前所有角色共用一个上限，标尺还没来得及答就被判死；
- **只重写被判错的那一方**：对拍不一致时由仲裁判定是题解、标尺还是生成器的问题，只改那一方；
- **证据优先于意见**：编排器会机械检查**题解自己过不过官方样例**。若题解过了样例、而标尺未校准或在
  大数值上跑不动，则**不会**凭标尺的输出去改题解，而是如实以 `unverified` 收尾；
- **只是"慢"的标尺不算错**：暴力解在官方样例上**纯 TLE**（没有答案错、没有崩溃；状态空间型暴力遇到 `10^9`
  必然爆炸）时，判定为"只是慢，不是算错"：它仍然是标尺，对拍降档到小规模随机数据（大数值交给题解与官方
  样例），报告里如实写明这一分工；只有答案错或崩溃才会重写标尺；
- **绝不修改生成器的数据**：编排器把规模上限与数值上限作为 `argv[1]`/`argv[2]` 交给生成器，
  发现超限只**回报给生成器**，不会自己去改数据（二进制串、下标这类"数字串"会被改坏）；
- **尊重跨变量约束**：题面里出现和 / 积形式的约束（`a_i + a_j ≤ 10^9`、`Σn ≤ 2·10^5` …）时，
  任何"把数值压小"的建议会被自动放弃；
- **坏标尺量出的反例一律丢弃**，绝不写进讲解。

### 预算（单轮成本上限）

| 限制 | 数值 |
| --- | --- |
| 单轮模型调用 | 40 次 |
| 单轮墙钟 | 20 分钟 |
| 题解重写 | ≤ 3 次（与"换标尺"解耦） |
| 暴力解校准尝试 | ≤ 3 次 |
| 空回复 / 截断重试 | 每次调用 1 次、整轮 3 次 |
| 同一组反例重复出现 | 停止重写，如实降级 |

真实测得的量级（DeepSeek 系推理模型、约 2000 分题）：

| 情形 | 调用 | 输出 token | 墙钟 | 费用 |
| --- | --- | --- | --- | --- |
| 一次通过 | 7 次 | ≈11.5 万 | ≈6 分钟 | ≈ ¥0.9 |
| 标尺重写一次 | 9 次 | ≈32 万 | ≈7 分钟 | ≈ ¥2.4 |

## 教练是一个"技能驱动"的 CF 助手（不只是讲题）

对话里的教练不是一段写死的提示词，而是一个**会按需加载技能、随手调工具**的助手：技能目录（只有
名字与一句话说明）常驻上下文，真正需要时才把完整流程读进来。所以你可以直接追问"这题为什么 WA"、
"帮我看看这份赛后复盘"、"这段代码边界对不对"，它自己决定去取题面、跑验证还是查提交记录。

| 技能 | 干什么 |
| --- | --- |
| `cf-explain` | 讲一道题（默认走完整验证流水线；「只给思路」也走它，只是不交付文档） |
| `cf-debug` | 评估你写的代码（贴了代码问为什么 WA，或提了个做法问行不行） |
| `cf-verify` | 只要机器验证结论，不要讲解 |
| `cf-fetch` | 只从 Codeforces 取题面与官方样例 |
| `cf-review` | **赛后复盘**（见下） |
| `cf-doc` | 生成图文讲解文档 |

技能就是 `skills/<名字>/SKILL.md`——带 YAML frontmatter 的 Markdown，**上面六个就是全部技能目录**。
想加自己的流程，新建一个目录写一份 `SKILL.md` 就行，不用改代码（`disable-model-invocation: true` 可以让它只在你手动点名时出现）。

配套工具：`skill` / `skill_read`（按需加载技能正文）、`cf_fetch`（取题面）、`cf_contract`（抽 I/O 契约）、
`cf_verify`（跑对拍验证）、`cf_run`（编译运行）、`cf_workspace`（读写本题工作区）、
`cf_submissions` / `cf_source`（提交记录与源码）、`cf_doc`（文档）。**材料已经取过的东西不会重复取**——
你粘了题面，应用会在模型动手之前把题面与样例**机械登记**进会话，教练不会再联网去扒一遍，
对拍与文档也直接读会话里的这一份；复盘材料里同样带着"已经在这里了，不用再去取"的标注。

### 交付形态也是自动的（不用先选"意图"）

输入框旁那个意图菜单默认是 **🤖 自动判断**，菜单里一共五项：**自动判断**（默认、推荐）、**完整讲解**、
**思路提示**、**题干解读**、**代码评估**——你只要正常说话，教练自己看你这句话在要什么：
**完整讲解**（"讲一下/怎么做"→ 出图文文档）、**思路提示**（"给点思路"→ 只给方向、不贴完整代码）、
**题干解读**（"没看懂题"）、**代码评估**（贴了代码问为什么 WA，或提了个做法问行不行）。
赛后复盘不在这个菜单里，它有自己的页面（见下）。
和技能一样，判断权在模型手里；**只粘题面或只给题号时一律按完整讲解做**，不会反问你"你要思路还是完整讲解"。

想固定行为时再手动指定那四项（会写进会话，之后每轮都按它走）。
自动模式下**实际选了什么会被记下来**（按它读的技能回填），画像证据与统计拿到的是"它真的做了什么"。

## 赛后复盘：把一场比赛的真实提交交给 AI 诊断

复盘页按 `handle + 比赛号` 拉取你在那场比赛里的**全部提交记录**，机械汇总（每题几次提交、判定序列、
卡了多久、罚时花在哪、白交了几发），再把两类**地面真相**装进一个新会话：

1. **官方题解**（CF 上有就取，没有就标注"没有找到"，让 AI 自己解题并跑验证，不编造）；
2. **选手源码**——每题最多三发：**首次提交 / 最后一次未通过 / 首次通过**，各带判定与用词。
   只看最后一发看不到"错在哪 → 怎么改对的"，而那正是复盘最值钱的地方。

装材料是流式的，界面上逐题报进度（`题解已装好｜源码 3/3 发`），超时的如实标注"超时未抓"。

两个入口：

- **🧠 开始 AI 复盘**：开一个带材料的新会话，并**自动让教练开讲**（不用你再打一句"开始吧"）；
- **💬 放进对话框**：材料直接落进输入框（不经过剪贴板），你可以改题、加上自己的问法再发。

> 提交源码页要求登录 Codeforces。第一次用先在复盘页点 **🔑 登录 Codeforces** 登一次，
> 登录态会长期保留（同一分区），之后的题面 / 题解 / 源码抓取都能直接用。
> 抓不到时会明说原因（未登录 / 比赛进行中源码隐藏 / `Source: N/A`），不会拿首页 HTML 冒充代码。

## 整理对话：文件夹 + 多选批量操作

对话多了以后，左侧侧边栏提供两件事：

**文件夹分类**

- 标签栏右侧的 📁 新建文件夹；把对话拖进分类用条目上的文件夹按钮（或选中多条后「移动到…」）；
- 文件夹标题栏可折叠（状态记在本地，刷新后保持）、可重命名、可删除；
- **删文件夹不删对话**：里面的对话回到「未分类」，删掉的只是分类；
- 分组顺序：置顶 → 各文件夹 → 未分类（未分类里仍按 今天 / 昨天 / 7 天内 分组）。

**多选批量操作**

- 标签栏右侧的 ✓ 进入多选模式：点条目即勾选（不会跳走），底部出现批量条；
- 「全选」选的是**当前可见**的对话（跟搜索词、当前标签页一致），不会把看不到的也选进来；
- 支持批量归档 / 取消归档 / 批量删除 / 批量移动到文件夹 / 批量置顶 / 批量取消置顶；操作完成后自动退出多选；
- 部分失败会如实说明失败了几条、为什么，不会只报一句"操作完成"。

**删除对话 = 连这道题的验证缓存一起删**

工作区是按**题号**跨会话复用的（同一道题第二次问会直接命中上次的对拍结论），所以删对话时会连它所属的
工作区一起清掉：确认框里会写明"这道题的题解 / 暴力解 / 对拍结论也会一起删"，下次问同一题就从零重新对拍。
如果还有别的对话在用同一份缓存，则保留并在提示里告诉你共用的对话是哪几个；想立刻重来而不删对话，
用题目面板里的 **🔄 重新对拍**（只清这道题的缓存）。

数据落在 `data/folders.json`（分类清单）与会话文件里的 `folder` 字段——都是本地文件，删掉即重置分类。

## 多题并行：同时问好几道题

**可以。** 每个对话各有自己的生成流（右侧「Agent 工作台」按对话显示），服务端没有"同时只能跑一个"的限制：
在 A 对话里问 1800C、切到 B 对话问 2264D，两轮会真的同时跑完，互不干扰（各自的工作区、各自的停止按钮）。

只有两处必须排队，都是**同一份共享资源**造成的，不是限流：

| 共享资源 | 怎么处理 | 你会看到什么 |
| --- | --- | --- |
| 取题用的内嵌浏览器窗口（全局只有一个，靠它过 Cloudflare） | 抓取排队：一次只放一个抓取进去，前一个失败不卡后面的 | 后一轮的控制台/日志里有「抓取排队中（前面还有 N 个抓取）」；题面照常取到 |
| 同一道题的工作区（`workspace/cf-<题号>`，按题号跨对话共享） | 同题加锁：同一道题的验证链串行 | 第二个对话要么排队后直接**复用**第一个的对拍结论，要么在它跑完后接着跑；绝不会两边同时改同一批文件 |

**不同题 = 不同锁**：并行度不受影响。同一道题第二次问命中已验证结论时，本来就不会重跑链路（见
「删除对话 = 连这道题的验证缓存一起删」）。

## 讲解形式

**完整讲解 / 代码评估 → 图文文档（默认）**；**思路提示 / 题干解读 → 轻量文字**（这两类只给方向，文档范式用不上）。

- 文档是自包含的 HTML 片段，套上内置设计系统后渲染在 **沙箱 iframe** 里（允许脚本、无同源权限、CSP 禁止一切外部请求）；
- 校验是机械的：标签 / class 白名单、禁脚本与外部 URL、标签配对、**图解数量（至少 1 张带合理 `viewBox` 的 `<svg>`）**、
  SVG 文字越界（**用 SVG 画的表格不算图解**：图元里必须有真正的线 / 路径，只有矩形和文字的网格按表格算）。不通过先给一次定向修复，再**机械挽救**（净化 + 补齐闭合标签 + LaTeX 翻译），
  只有"确实一张图都没有"才回落成文字讲解；
- **图是硬性交付条件，但"画什么"交给必要性判断**：提示词里明确了哪些地方值得画（算法状态怎么一步步变、
  数据结构或几何的形态、构造怎么摆、反例/边界长什么样）、哪些不值得（纯推导、模板、把样例抄一遍、
  "开始→读入→输出"的空壳流程图），判据是一句话——**把这张图删掉，学员会不会变难懂？** 不会就别画。
  所以"至少 1 张"是底线，不是配额：我们不为凑数生成没有信息量的图；
- 消息正文只放一句引子；文档在生成过程中**实时写入 Agent 工作台**，看得见进度；文档**一到就渲染进对话**
  （不用等整轮结束才冒出来），并自带打包好的样式表与脚本（深浅色主题自适应），不会再出现黑字黑底；
- 模型若写了 LaTeX（`$x$`、`\le`、`\lfloor`…），净化器会翻译成可读文本或设计系统的公式组件——
  因为图文文档里没有公式渲染器。

## 花费是怎么算的

每条消息下方显示 `💸 N 次调用 · ≈ ¥X`；侧栏给出本轮花费与**按 Agent 拆分**的明细，决策轨迹里每次调用都有耗时、token 与模型名。

- token 取自服务商的 `usage`；服务商不返回时按字符估算并明确标注；
- **缓存命中有单独计价**：DeepSeek 这类服务对命中的输入按折扣价计费，应用会读
  `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 分别计价；两者都没有时，估算会标注
  "**未含缓存折扣，实际通常更低**"；
- 单价：你在设置里填的 `providerId::model` 覆盖值优先，其次内置参考价；两者都没有就只报 token、
  显示"未配置单价"，不编数字；
- `max_tokens` 默认不指定（用服务商默认值）。推理型模型会把预算先花在思考上，上限设小了会出现"正文为空"，
  所以程序在检测到"被长度上限截断"时会自动换一种问法重试，并在必要时去掉上限。

- 数据目录：打包版就在 exe 旁的 `data/`（便携，整个文件夹拷走即迁移），桌面版与浏览器通道的诊断日志在
  `%APPDATA%\codeforces-coach`。两者都写在 `.gitignore` 里、**永不进入仓库**——仓库里只有源码与技能，
  不会有你的对话、工作区、题面缓存或密钥；
- 无遥测、无账号、无统计上报。唯一的对外请求是你配置的模型 API，以及取题时的 codeforces.com
  （CF 页面自己会去加载 Cloudflare 的挑战资源，那是页面的行为，不是我们在上报）；
- Python / Node 生成的代码运行在受限沙箱里（独立临时目录、默认禁网）。
  **C++ 无法用这种方式限制**，只做超时与进程树清理——请只使用你信任的模型。
- 富文档运行在带 CSP 的沙箱 iframe 中，禁止一切外部请求。

### 从 Codeforces 取题

CF 挂在 Cloudflare 后面：普通 HTTP 请求可能吃 `403 + cf-mitigated: challenge`，但官方 `/api/*` 接口不被拦。
应用按顺序尝试：普通 HTTP（只请求桌面版，识别并拒绝移动版）→ 内嵌 Chromium 窗口（先隐藏窗口，再**可见但在
屏幕外**的窗口，因为 Cloudflare 的挑战常常会拒绝不可见窗口）→ 本地题面缓存 → 本会话缓存的官方样例 →
最后才提示你直接粘贴题面（这条路径永远可用、不依赖网络）。`data/cf-fetch.log` 会记录每一步的结果。

**地址必须对，结论才敢下**：题目的规范地址是 `https://codeforces.com/contest/<比赛号>/problem/<题号>`
（gym 走 `/gym/<比赛号>/problem/<题号>`），`/problemset/problem/...` 只在题目进了题库总表之后才存在，
所以取题按"规范地址优先、题库地址兜底"来试。某场比赛的题表取自权威的 `contest.standings` 接口
（不带附加参数时可以匿名调用），而**否定结论只在权威来源确认后才给出**：题号不存在要由这场比赛自己的
题表说话，比赛不存在要由比赛总表说话——绝不因为抓取被拦或失败就说成"这道题不存在"。
抓不到时会弹一个对话框说清是哪一类（没有这道题 / 被反爬拦截 / 题面没能取到），并给两个按钮：
**在浏览器打开这道题**、**我自己粘贴题面**（只有点后者才会往输入框里填模板）。

## 常见问题

- **取题失败 / 提示"被反爬拦截"？** 现在会弹对话框**说准原因**，先看清楚是哪一种：
  - `没有题号 X；该比赛的题号是：…` → 题号写错了（题号表来自**这场比赛自己的题表**，刚结束的比赛也算数）。
  - `没有比赛 N` → 比赛号写错了，或那是 gym / 未公开比赛（gym 需要先在应用里登录 CF）。
  - 真的反爬（Cloudflare）→ 提示里会明确写"反爬拦截"；那时可以配代理、稍后重试，或直接把题面粘进输入框
    （粘贴走的是完全相同的流水线）。
  - 排查线索两份：`data/cf-fetch.log`（每次抓取的成败与原因）与
    `%APPDATA%\codeforces-coach\cf-diag.log`（浏览器通道每一步的落地页、是否遇到挑战；**失败一定会写**，不需要开开关）。
- **为什么回答里说"我没能验证通过"？** 验证是承诺而不是装饰：预算内没收敛就如实说，并列出试过什么。
- **我的电脑没装 g++ / Python，还能用吗？** 能，但交付形态会如实降级（这是刻意的，不是故障）：
  - 应用**每次**都探测本机运行时（30 秒缓存），工具描述与系统提示词里写的就是"你这台机器上有什么"；
  - 只有 Python → 验证链**自动改用 Python** 跑，并在结论里注明"本机没有 cpp 运行时，已改用 python"；
  - **一个都没有** → `cf_verify` 直接回 `NO-RUNTIME` 并明确要求"不要再重试"，讲解按**纯推理**交付：
    第一句如实说明"本机没有编译器，这道题没能用程序验证"，但思路、正确性论证、复杂度、图文文档照常给。
    装好 Python 3（或 g++）后 30 秒内自动重新探测，不需要重启应用。
- **答案里出现过一坨带尖括号、`DSML` 字样的怪东西？** 那是**上游模型把内部工具调用标记泄漏成了正文**
  （不是编码问题，也不是你的操作问题），已在三处堵住：
  ① 步数用尽时不再省略工具声明（改为 `tool_choice: none` + 明确指令——省略声明正是触发泄漏的条件）；
  ② 正文里的标记优先**回收**成真正的工具调用继续干活，收不回来就剥掉，**绝不**当讲解显示；
  剥完为空则如实说明这一轮没产出正文，再要一次；
  ③ 打开旧会话时顺手清理历史里已经存下的标记并写回文件（老会话不用手动删）。
- **为什么有时又慢又贵？** 推理型模型单次调用可能 5 分钟；预算把单轮限制在 40 次调用 / 20 分钟。
  最有效的省钱手段是给角色分别配模型（生成器用便宜的、题解用强的）。
- **什么都没生成出来？** 你会拿到一段机械摘要：卡在哪、已经跑了什么、可以怎么办，外加完整的决策轨迹——
  一轮讲解不会以空消息结束。
- **我的数据在哪？** 打包版在 exe 旁的 `data/`（桌面版与诊断日志在 `%APPDATA%\codeforces-coach`）；
  整个删掉即彻底重置。这些目录都写在 `.gitignore` 里，不会跟着仓库走。

## 已知边界

- 架构消除的是**实现缺陷的相关性**（暴力解写错、题解漏边界、溢出…），**消除不了题意误读的相关性**：
  几个 Agent 共享同一份题面与同一套先验，题面本身有歧义时会一致地犯同一个错。官方样例是模型之外唯一的锚点。
- 官方样例只能证明输出格式，不能证明正确性——所以它始终与机械检查和对拍叠加使用。
- **交互题不支持**（需要实时交互的题目无法用标准输入输出对拍）。
- **C++ 代码无法沙箱化**：生成的代码会在你的机器上真实运行。
- 长推理模型的输出截断仍是真实的失败模式：程序会用"只要代码"的问法与更大的输出上限重试，
  再失败就如实降级说明。
